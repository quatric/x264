Mobiclip regression tests
========================

Configure with --enable-static and 8-bit support, then run:

    make check-mobiclip

The C API tests check:

- Slice count, byte limits and macroblock limits cannot split Mobiclip frames,
  while standard H.264 still supports multiple slices.
- Standard H.264 retains caller SEI, HRD timing, recovery-point and frame-packing
  messages with single-threaded and frame-threaded encoding.
- Non-finite floating-point options and values overflowing float storage are rejected.
- Integer option overflow and undefined Mobiclip mode values are rejected.
- Explicit keyint=1 produces only keyframes.
- Mobiclip CRF and CRF maximum retain values through 63; H.264 keeps its ceiling of 51.
- QP/CRF below 12 cannot activate H.264 lossless coding or invert QP bounds.
- Unsupported chroma formats and 10-bit Mobiclip are rejected at encoder open.
- I420, YV12, NV12 and NV21 versions of the same samples produce identical
  encoded slice bytes, including predicted frames.
- QP 0 is clamped to the format floor and produces the same slices as QP 12.
- Reconstructed pictures are labelled I420 and --dump-yuv writes the same
  Y, U and V samples as the public reconstruction API.

The tests use synthetic frames and need no external files or decoder.
They exercise the public API and run independently of the assembly tests.
